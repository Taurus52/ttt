Техническое задание на разработку Telegram-бота для выбора ревьюера кода (v.2.0)
1. Введение
1.1. Наименование проекта: CodeReview Bot (CRBot).
1.2. Цель: Автоматизация и рационализация процесса выбора ревьюера кода через равномерное распределение нагрузки внутри команд.
1.3. Технологический стек:

Язык программирования: Python 3.11+

Фреймворк для бота: python-telegram-bot (v20+ с использованием ApplicationBuilder и контекстного подхода).

База данных: PostgreSQL (v12+).

ORM: SQLAlchemy Core + asyncpg или Django ORM (на усмотрение разработчика, но с указанием в документации).

Хостинг: Предполагается развертывание на VPS/облачном сервере (Ubuntu 22.04 LTS).

Контейнеризация: Приветствуется использование Docker и Docker Compose для упрощения деплоя.

2. Функциональные требования
2.1. Роли пользователей
Администратор: Определяется значением в переменной окружения ADMIN_TG_ID. Имеет полный контроль над системой.

Тимлид: Назначается администратором на конкретную команду. Исключается из автоматического выбора, но может получать задачи эскалации.

Разработчик: Основной пользователь системы. Может запрашивать ревью и быть выбранным ревьюером.

2.2. Команды для Администратора (Критически важно)
Администратор имеет доступ к следующим командам через бот:

/admin_create_team <название_команды> - Создает новую команду. Название должно быть уникальным.

/admin_list_teams - Выводит список всех команд с их ID и названиями.

/admin_add_user <telegram_id> <название_команды> - Добавляет пользователя в указанную команду. Бот должен предварительно проверить, что пользователь запустил его хотя бы раз (/start).

/admin_set_team_leader <telegram_id> <название_команды> - Назначает тимлида для команды. В одной команде может быть только один тимлид. При назначении нового предыдущий тимлид автоматически лишается этого статуса.

/admin_remove_user <telegram_id> <название_команды> - Удаляет пользователя из команды.

/admin_deactivate_user <telegram_id> - Временно деактивирует пользователя во всех командах (исключает его из всех "кругов").

/admin_activate_user <telegram_id> - Reactivate пользователя.

/admin_get_user_id <@username> - Вспомогательная команда для получения telegram_id по username.

2.3. Процесс onboarding пользователя
Пользователь запускает бота командой /start.

Бот приветствует его и показывает список команд, в которые пользователь добавлен администратором.

Если пользователь не добавлен ни в одну команду, бот сообщает: "Вы не добавлены ни в одну команду. Обратитесь к администратору."

Если добавлен, бот сохраняет его tg_id и username в базу данных.

2.4. Алгоритм выбора ревьюера ("Круг")
Для каждой команды ведется свой независимый "круг".

"Круг" реализуется как отдельная таблица в БД (review_cycles), которая хранит:

team_id (FK)

current_cycle (JSONB) - Текущая перемешанная очередь из user_id активных разработчиков команды.

current_index (Integer) - Указатель на следующего ревьюера в очереди current_cycle.

Логика выбора:

При запросе на ревью из очереди исключаются: автор запроса и тимлид команды.

Бот берет ревьюера из current_cycle[current_index] и увеличивает current_index на 1.

Если current_index достигает конца очереди, круг считается завершенным. Бот:

Формирует новый current_cycle из актуального списка активных разработчиков команды (за исключением тимлида).

Перемешивает новый список случайным образом.

Сбрасывает current_index в 0.

Новый пользователь, добавленный в команду, попадает в круг только при формировании следующего цикла.

2.5. Запрос на ревью
Пользователь вводит /request_review.

Если пользователь состоит в нескольких командах, бот запрашивает уточнение (кнопками).

Бот запрашивает ссылку/ссылки на Merge Request (GitLab). Происходит базовая валидация (наличие gitlab.com и merge_requests в строке).

Бот выбирает ревьюера по алгоритму "круга".

Бот создает запись в таблице review_requests и обновляет индекс в review_cycles.

Ревьюеру отправляется сообщение с кнопками действий.

2.6. Обработка действий ревьюера
Кнопки под сообщением:

✅ Approve -> Уведомление автору, запись в БД.

🔄 Request Changes -> Уведомление автору, запись в БД.

➡️ Escalate to TL -> Сообщение тимлиду: "Вам эскалировано ревью от [@author] для разрешения спорных моментов. Ссылки: [ссылки]". Важно: Первоначальный ревьюер при этом считается выполнившим свою очередь в круге.

3. Нефункциональные требования
Производительность: Отклик бота на команды пользователя должен быть <2 секунд.

Безопасность:

Все чувствительные данные (токен бота, данные для подключения к БД) хранятся в переменных окружения.

Доступ к командам администратора проверяется по user_id.

Масштабируемость: Архитектура должна допускать возможность добавления новых платформ (например, Slack) в будущем без полного переписывания кода.

Логирование: Все действия администратора и ошибки должны логироваться в файл и/или Sentry.

4. Структура базы данных (Финализированная)
sql
-- Таблица пользователей
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    tg_id BIGINT UNIQUE NOT NULL, -- ID пользователя в Telegram
    tg_username VARCHAR(32),
    is_active BOOLEAN DEFAULT TRUE
);

-- Таблица команд
CREATE TABLE teams (
    id SERIAL PRIMARY KEY,
    name VARCHAR(64) UNIQUE NOT NULL
);

-- Связь пользователей и команд (многие-ко-многим)
CREATE TABLE user_teams (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    team_id INTEGER REFERENCES teams(id) ON DELETE CASCADE,
    UNIQUE(user_id, team_id)
);

-- Таблица тимлидов (один тимлид на команду)
CREATE TABLE team_leaders (
    id SERIAL PRIMARY KEY,
    user_id INTEGER UNIQUE REFERENCES users(id) ON DELETE CASCADE, -- Один пользователь - тимлид только одной команды
    team_id INTEGER UNIQUE REFERENCES teams(id) ON DELETE CASCADE -- Одна команда - один тимлид
);

-- Таблица для хранения состояния "круга"
CREATE TABLE review_cycles (
    id SERIAL PRIMARY KEY,
    team_id INTEGER UNIQUE REFERENCES teams(id) ON DELETE CASCADE,
    current_cycle JSONB NOT NULL, -- Массив user_id (INTEGER[]) или JSONB-массив
    current_index INTEGER DEFAULT 0 NOT NULL
);

-- Таблица запросов на ревью
CREATE TABLE review_requests (
    id SERIAL PRIMARY KEY,
    author_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    reviewer_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    team_id INTEGER REFERENCES teams(id) ON DELETE CASCADE,
    mr_links JSONB NOT NULL, -- Массив ссылок
    status VARCHAR(20) NOT NULL, -- 'assigned', 'approved', 'rework'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
5. Деплой и конфигурация
Переменные окружения (.env):

BOT_TOKEN - Токен Telegram-бота от @BotFather.

ADMIN_TG_ID - ID администратора в Telegram.

DATABASE_URL - Строка подключения к PostgreSQL (напр., postgresql+asyncpg://user:pass@host:5432/dbname).

LOG_LEVEL - Уровень логирования (INFO, DEBUG).

Развертывание: Предоставить docker-compose.yml для запуска бота и БД в контейнерах.
