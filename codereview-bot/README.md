# CodeReview Bot (CRBot)

Telegram-бот для автоматизации процесса выбора ревьюера кода с равномерным распределением нагрузки внутри команд.

## 🚀 Основные возможности

- **Автоматический выбор ревьюера** по алгоритму "круга" с равномерным распределением
- **Управление командами** - создание команд, добавление участников, назначение тимлидов
- **Гибкая система ролей** - администратор, тимлид, разработчик
- **Интеграция с GitLab** - валидация ссылок на Merge Requests
- **Эскалация тимлиду** при необходимости разрешения спорных моментов
- **Уведомления в реальном времени** о статусе ревью

## 📋 Требования

- Python 3.11+
- PostgreSQL 12+
- Docker и Docker Compose (для контейнерного развертывания)
- Telegram Bot Token (получить у @BotFather)

## 🛠️ Быстрый старт

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd codereview-bot
```

### 2. Настройка конфигурации

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Отредактируйте `.env` и укажите необходимые параметры:

```env
# Обязательные параметры
BOT_TOKEN=your_telegram_bot_token_here
ADMIN_TG_ID=your_telegram_id_here
DB_PASSWORD=strong_password_here

# Остальные параметры можно оставить по умолчанию
```

### 3. Запуск с Docker Compose

```bash
./scripts/deploy.sh
```

Или вручную:

```bash
docker-compose up -d
```

### 4. Проверка статуса

```bash
docker-compose ps
docker-compose logs -f bot
```

## 📱 Использование бота

### Команды для всех пользователей

- `/start` - Регистрация в системе и просмотр своих команд
- `/help` - Справка по командам
- `/my_teams` - Список команд, в которых вы состоите
- `/request_review` - Запросить ревью кода

### Команды администратора

- `/admin_create_team <название>` - Создать новую команду
- `/admin_list_teams` - Список всех команд
- `/admin_add_user <telegram_id> <команда>` - Добавить пользователя в команду
- `/admin_set_team_leader <telegram_id> <команда>` - Назначить тимлида
- `/admin_remove_user <telegram_id> <команда>` - Удалить из команды
- `/admin_deactivate_user <telegram_id>` - Деактивировать пользователя
- `/admin_activate_user <telegram_id>` - Активировать пользователя
- `/admin_get_user_id @username` - Получить ID пользователя

## 🔄 Процесс работы

### Запрос ревью

1. Разработчик вводит `/request_review`
2. Выбирает команду (если состоит в нескольких)
3. Отправляет ссылки на GitLab Merge Requests
4. Бот автоматически выбирает ревьюера по алгоритму "круга"
5. Ревьюер получает уведомление с кнопками действий

### Действия ревьюера

- **✅ Approve** - Одобрить код
- **🔄 Request Changes** - Запросить изменения
- **➡️ Escalate to TL** - Эскалировать тимлиду

### Алгоритм выбора ревьюера

Бот использует алгоритм "круга" для равномерного распределения:

1. Для каждой команды ведется отдельная очередь
2. Участники перемешиваются случайным образом
3. Ревьюеры выбираются последовательно
4. После прохода всех участников круг обновляется
5. Тимлиды и авторы запросов исключаются из выбора

## 🔧 Развертывание на сервере

### Автоматическая установка (Ubuntu 22.04)

```bash
# Скопируйте проект на сервер
scp -r codereview-bot/ root@your-server:/opt/

# Подключитесь к серверу
ssh root@your-server

# Запустите скрипт установки
cd /opt/codereview-bot
./scripts/server_setup.sh

# Настройте .env файл
nano .env

# Запустите бота
./scripts/deploy.sh
```

### Systemd сервис

После установки бот будет доступен как systemd сервис:

```bash
# Запуск
systemctl start codereview-bot

# Остановка
systemctl stop codereview-bot

# Статус
systemctl status codereview-bot

# Автозапуск
systemctl enable codereview-bot
```

## 🐛 Решение проблем

### Бот не запускается

1. Проверьте правильность токена бота в `.env`
2. Убедитесь, что PostgreSQL запущен
3. Проверьте логи: `docker-compose logs bot`

### Ошибка подключения к БД

1. Проверьте параметры подключения в `.env`
2. Убедитесь, что PostgreSQL доступен
3. Попробуйте пересоздать контейнеры: `docker-compose down && docker-compose up -d`

### Пользователь не может запросить ревью

1. Убедитесь, что пользователь добавлен в команду
2. Проверьте, что пользователь активен
3. Убедитесь, что в команде есть другие активные участники

## 🔒 Безопасность

1. **Никогда** не коммитьте файл `.env` в репозиторий
2. Используйте сильные пароли для базы данных
3. Ограничьте доступ к серверу через firewall
4. Регулярно обновляйте зависимости
5. Используйте HTTPS для веб-интерфейсов (Adminer)
